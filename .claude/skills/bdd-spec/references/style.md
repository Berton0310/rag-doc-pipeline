# Feature 撰寫風格

## 語言

- Gherkin 關鍵字用英文：`Feature`、`Background`、`Scenario`、`Scenario Outline`、`Examples`、`Given`、`When`、`Then`、`And`、`But`。
- 步驟內容用繁體中文。
- 原因：BDD 執行器是否支援中文關鍵字尚未驗證，英文關鍵字最保險。

## 原則

1. **一個情境只驗一種行為**。如果 Then 裡出現「並且還要……」，多半該拆成兩個情境。
2. **只寫看得到的結果**：輸出檔內容、回傳值、錯誤訊息、日誌。不寫內部變數、類別名稱、演算法。
3. **用具體資料**：寫「第 3 頁沒有文字層」，不寫「某些頁面是掃描的」。
4. **門檻要寫數字**：寫「寬或高小於 32 像素的圖片被丟棄」，不寫「太小的圖片被丟棄」。
5. **禁用無法驗證的詞**：「正確」「合理」「適當」「良好」「快速」。如果真的只有人能判斷，就標 `@manual`，並寫清楚人要看什麼。
6. **相同前提放 Background**，多組輸入用 `Scenario Outline` 加 `Examples` 表格。
7. **失敗行為也要寫**：檔案壞掉、端點連不上、模型回傳格式錯時，系統要怎麼反應。

## 範例

不好：

```gherkin
Scenario: 處理圖片
  When 解析文件
  Then 圖片應該被正確處理
```

好：

```gherkin
Scenario: 跨頁重複出現的圖片視為 logo 並丟棄
  Given 一份 5 頁的 PDF，每頁右上角都有同一張 120x40 像素的圖片
  When 執行圖片過濾
  Then 這張圖片的過濾結果是 "丟棄"
  And 丟棄原因是 "重複出現於 5 頁"
```

人工驗證的寫法：

```gherkin
@manual
Scenario: 換膠步驟照片的描述包含操作重點
  Given 仿真 SOP 第 4 頁的步驟 5 照片（標示關閉進膠閥）
  When 產生圖片描述
  Then 人工確認描述有提到「關閉」與「進膠閥」
  And 人工確認描述沒有出現照片裡不存在的部件
```
