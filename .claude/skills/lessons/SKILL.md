# 錯誤教訓

## 開工前查詢

1. 讀 `docs/lessons/INDEX.md`（每條一行）。
2. 只打開標籤含你要動的模組或 `all` 的條目。不要全部讀。

## 什麼時候記錄

兩層記錄：

1. **每一個錯誤**都寫進自己任務報告的「遇到的錯誤」欄（implementer 的 impl 報告、verifier 的 verify 報告）。主 session 會逐條檢查有沒有該升級成 lesson 的。
2. **符合下列任一條**，再另外記成 lesson：
   - 花了不只一次嘗試才修好
   - 驗證退件（FAIL）的原因
   - 環境、套件、作業系統差異造成的問題
   - 誤讀規格或任務檔

## 怎麼記錄

1. 先在 INDEX 找有沒有同類條目。有的話在那條補一次「再次發生」紀錄，不要重複新增。
2. 新增 `docs/lessons/L-<四位數編號>-<簡短名稱>.md`，編號接 INDEX 最後一號：

```markdown
# L-0001 <一句話標題>

- 日期：YYYY-MM-DD
- 標籤：<模組名稱或 all>, <類型：環境 / 套件 / 規格誤讀 / 邊界 / 測試>
- 任務：T-xxx
- 發生次數：1

## 症狀
<看到什麼錯誤，貼關鍵錯誤訊息原文>

## 根本原因
<為什麼會發生>

## 規則
<以後要怎麼做才不會再發生，一兩句>

## 能否自動偵測
<能的話，寫用什麼檢查可以抓到；已升級為自動檢查時寫明位置>
```

3. 在 `docs/lessons/INDEX.md` 加一行：`- [L-0001](L-0001-xxx.md) <標籤> — <規則的一句話>`
