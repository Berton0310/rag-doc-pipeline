# T-000 人工驗證

| # | 情境 | 要打開什麼 | 要看什麼 | 預期 | 結果（使用者填） | 備註 |
|---|---|---|---|---|---|---|
| 1 | install.feature：在 GPU 機器上照 README 完成安裝（@manual @gpu） | GPU 機器上的終端機，以及 repo 根目錄的 `README.md`「安裝」段落（步驟 1 到 4） | 在一台沒有裝過本專案的 GPU 機器上，只照 README「安裝」段落逐步操作，最後執行 `uv run ragdoc --version` | 不需要 README 以外的步驟就完成安裝；`uv run ragdoc --version` 印出 `ragdoc 0.1.0`（版本號與 `pyproject.toml` 的 `version` 相同） | ☐ 通過 ☐ 不通過 | |
| 2 | guard_hook.feature：實際派發的 implementer 被擋下，且看得懂原因（@manual） | 主 session 派發一個「要求修改 `features/tooling/check.feature`」的測試任務給 implementer；之後看 `git status`、`git diff features/tooling/check.feature`，以及 implementer 的回報 | `features/tooling/check.feature` 是否有變動；implementer 回報中對被擋下的描述 | `features/tooling/check.feature` 沒有任何變動（`git diff` 無輸出）；implementer 的回報中看得出它被 hook 擋下、原因是受保護路徑，並提到應改寫進實作報告的「疑義」欄 | ☐ 通過 ☐ 不通過 | hook 定義在 `.claude/agents/implementer.md` frontmatter 的 `hooks`（matcher `Write\|Edit`） |
| 3 | guard_hook.feature：主 session 與 verifier 不受這個 hook 影響（@manual） | 主 session 與 verifier 各用 Edit 修改 `tests/bdd/` 底下的一個檔案（例如在註解加一行，確認後還原） | 兩次 Edit 是否成功；檔案內容是否真的改變 | 兩者的 Edit 都成功，沒有出現「已擋下對受保護路徑的修改」訊息，檔案內容確實被修改 | ☐ 通過 ☐ 不通過 | 測完記得還原 `tests/bdd/` 的修改 |
