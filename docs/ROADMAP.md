# 開發分期

> 使用者 2026-11-12 決定：MVP 採「從頭到尾的細流程」（每一層都有、每一層只做最簡單的版本），之後分期補齊。
> 任務編號為預定，實際建立任務檔時以 `docs/tasks/README.md` 為準。每個任務仍要先討論規則、寫 feature、經使用者核准才派發。

## MVP：筆電可跑的細流程

**目標**：證明研究前提——在 SOP 類文件上，依結構切塊的檢索效果比固定長度切塊好。

**限制**：
- 在開發筆電上就能跑：不需要 GPU；除了 T-008 產生問答以外不需要網路。
- 只用仿真文件（自己產生、結構乾淨、陷阱可控）。

| 任務 | 內容 | 這一期先不做 |
|---|---|---|
| T-000 | 開發環境（安裝、check、scope_check、模組邊界、路徑防護 hook） | — |
| T-001 | 中間格式（`contracts`） | — |
| T-002 | 仿真 SOP：3~5 份**原生** PDF，含標題、編號步驟、有框參數表、步驟照片、重複 logo | 掃描檔、無框表格 |
| T-003 | 逐頁判斷（`probe`）：判斷原生或掃描；掃描頁標為「略過，需要 OCR」 | 混合頁、亂碼判斷 |
| T-004 | 原生解析（`parsers.native`）：PyMuPDF 抽文字與座標；用字型大小判斷標題；有框表格轉 HTML；取出內嵌圖片 | 版面模型、無框表格 |
| T-005 | 圖片過濾（`enrich`）：規則（L1）與重複圖（L2）兩層，不需要模型 | 分類模型（L3）、圖片描述 |
| T-006 | 輸出與 CLI（`output`、`pipeline`、`cli`）：`ragdoc parse <pdf> -o <dir>` | — |
| T-007 | 兩種切法：固定長度、依標題與步驟 | 更多策略 |
| T-008 | 自動評估：LLM 從仿真文件產生問答（`@network`，只送仿真文件）；本地小型 embedding 模型＋記憶體內檢索；計算前 k 筆命中率，輸出比較報告 | 自動選出最佳切法 |
| T-009 | 前端檢視頁（`web`，使用者 2026-11-12 決定放進 MVP）：上傳 PDF 並執行解析；轉換結果（原始頁面疊上元素框，與解析內容點選連動）；切分結果（頁面上顯示每塊範圍，兩種切法並排比較）；評估報告（每題檢索到哪幾塊、是否命中） | 修改或校正結果、多人使用、登入 |

**完成標準**：對 T-002 的仿真文件跑完 T-008，產出兩種切法的命中率比較報告，並由使用者在 T-009 的檢視頁上檢視（`@manual`）。

**T-009 的設計原則**：
- 只開放 `127.0.0.1`，不對外。
- 前端不自己解析 PDF，只呼叫管線、讀取輸出檔。
- 技術：FastAPI 加原生 HTML/JS（不需要前端編譯工具），以便精確控制頁面疊框與點選連動。使用者未另行指定，採此建議；開工討論 feature 時可再調整。

## 第二期：掃描與版面

- 版面模型 PP-DocLayoutV3（ONNX、CPU），原生頁與掃描頁共用
- GLM-OCR 處理掃描頁（WSL2 + vLLM，`@gpu`）
- 混合頁、亂碼判斷、解析度規則（`docs/DESIGN.md` §5.3）
- 仿真文件加入掃描頁與混合頁
- 兩種部署方式實測比較（WSL2 + vLLM vs Windows + Ollama）

## 第三期：圖片與表格品質

- 圖片描述：VLM，帶入前後文（開發期用 OpenRouter，只送仿真文件）
- 圖片過濾 L3：分類模型（SigLIP 2 / CLIP）
- **無框表格**（使用者 2026-11-12 指定放這一期）：
  - 偵測：版面模型＋文字對齊分析雙重檢查
  - 結構：原生頁用座標對齊分析，掃描頁用 VLM 讀取表格區域（300 dpi）
  - 交叉比對，結果不一致標為低信心；沒把握時保留對齊的純文字，不硬轉成表格
  - 以 TEDS 評分；仿真文件加入純空白對齊、只有表頭底線、合併儲存格、跨頁等無框表格
  - 開工前派 agent 查證無框表格專用模型與最新跑分
- 跨頁表格合併、頁首頁尾、閱讀順序

## 第四期：研究核心

- 更多切法候選
- **自動選出最佳切法**
- 決定處理真實文件時的圖片描述模型（`docs/DESIGN.md` §5.4 待決議題）
